Publicar las herramientas de emprendimiento

De tu computador a vercel.app, con el registro de cada cambio en GitHub. La primera parte se hace una sola vez; la segunda es la que vas a repetir cada vez que cambies algo.

Antes de empezar

Descomprime emprendimiento-cdp-repo.zip en una carpeta de tu computador. Ya trae el repositorio de Git iniciado y el primer commit hecho, así que no hace falta git init.

Comprobar que quedó bien
$ cd ruta/a/emprendimiento-cdp
$ git log --oneline
9ae0f5b Portada de emprendimiento y las dos primeras herramientas

Si ves esa línea, el repositorio está listo. Necesitas Git, Python 3 y Node instalados: Python genera las páginas y Node comprueba que el JavaScript sea válido antes de publicar.

Una sola vez: conectar GitHub y Vercel

Estos cinco pasos van en orden y cada uno depende del anterior.

  1. Crea el repositorio en GitHub

    En GitHub, New repository. Nómbralo emprendimiento-cdp. Déjalo vacío: sin README, sin .gitignore, sin licencia. El proyecto ya trae los suyos y si GitHub crea otros, el primer push choca.

  2. Apunta tu carpeta a ese repositorio

    Copia la dirección que te da GitHub y, en la carpeta del proyecto:

    Terminal
    $ git remote add origin https://github.com/TU-USUARIO/emprendimiento-cdp.git
$ git push -u origin main

    Recarga GitHub: deben aparecer los archivos.

  3. Importa el proyecto en Vercel

    En Vercel, Add New → Project, y elige emprendimiento-cdp de la lista de tus repositorios de GitHub.

  4. No configures nada

    Vercel intentará adivinar un framework. Déjalo en Other y deja vacíos los campos de Build Command y Output Directory.

    Esto importa. Son tres HTML ya construidos, no una aplicación que Vercel deba compilar. Si le pones un Build Command, fallará el despliegue buscando un package.json que no existe.

    Las páginas se construyen en tu computador con ./construir.sh, antes del commit. Vercel solo sirve el resultado.

  5. Deploy

    En menos de un minuto tienes tu dirección, del estilo emprendimiento-cdp.vercel.app. Ábrela y comprueba lo mismo que comprobamos aquí: que los dos botones abren su herramienta, y que «Volver a las herramientas» regresa a la portada.

Cada vez que cambies algo

Este es el ciclo que vas a repetir. Son cuatro órdenes y siempre las mismas.

El ciclo completo
# 1 · edita lo que quieras dentro de src/

# 2 · genera las tres páginas y compruébalas
$ ./construir.sh
Las tres páginas están listas para publicar.

# 3 · guarda el cambio con su explicación
$ git add -A
$ git commit -m "Qué cambió y por qué"

# 4 · publícalo
$ git push

Vercel detecta el push y publica solo. No hay que entrar a su panel.

Si construir.sh falla, no hagas push. Termina con error y dice exactamente qué comprobación no pasó: una tilde rota, un logo sin incrustar, el JavaScript con un error de coma. Ese es el momento barato de arreglarlo. Después del push, el fallo ya está publicado.

Qué se edita y qué se genera

La regla es una: nunca edites un HTML de la raíz. Los genera construir.sh y el siguiente build los sobreescribe sin avisar, con tu cambio dentro.

emprendimiento-cdp/ ├── index.html ← se genera ├── ficha-negocio.html ← se genera ├── tablero-financiero.html ← se genera ├── construir.sh └── src/ ├── fuente.html ← la portada: aquí se edita ├── aplicar.py ← viste las dos herramientas ├── _comun.py ← paleta, pie y barra de volver └── originales/ no tocar
Se edita a mano Lo genera el build

aplicar.py parte siempre de src/originales/, nunca del resultado anterior. Por eso puedes ejecutar ./construir.sh las veces que quieras y sale idéntico; si partiera de su propia salida, cada ejecución añadiría otro pie y otra barra de volver.

Tareas frecuentes

Quiero…Se toca
Cambiar un texto de la portada src/fuente.html
Cambiar el pie o los colores de las dos herramientas src/_comun.py
Activar una herramienta que dice «Próximamente» src/fuente.html: añade su dirección en DIRECCIONES y quita data-pronto de su tarjeta
Que el navegador deje de mostrar la versión vieja Sube VERSION en src/fuente.html y en src/aplicar.py
Ver un cambio antes de publicarlo Abre el HTML de la raíz con doble clic

Si algo sale mal

El despliegue de Vercel falla

Casi siempre es un Build Command puesto donde debía ir vacío. En Vercel: Settings → General → Build & Development Settings, y deja Framework en Other con los campos vacíos.

Publiqué algo roto

En Vercel, Deployments, busca el despliegue anterior que sí funcionaba y usa Promote to Production. El sitio vuelve atrás en segundos. Después arreglas con calma en tu computador.

Se ven tildes rotas

No debería pasar: construir.sh lo comprueba. Si ocurre, es que se editó un HTML de la raíz a mano en vez de src/. Ejecuta ./construir.sh y vuelve a publicar.

El repositorio incluye su propio README.md con esta misma información, para quien abra el proyecto dentro de un año sin haber visto esta página.
